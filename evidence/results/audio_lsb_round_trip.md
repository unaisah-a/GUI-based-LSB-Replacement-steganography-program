# Audio LSB Round-Trip Results

Generated by `tests/test_audio_stego.py`. Do not edit by hand: an earlier hand-written version of this file went stale and described a payload format the code no longer uses.

## What is being established

That a payload embedded in a 16-bit PCM WAV cover extracts back byte-for-byte at every selectable LSB depth from 1 to 8, from a non-zero start location.

## The encoded stream

The audio layer writes a **bare 4-byte big-endian payload length followed by the payload bytes**, and nothing else. It is identical to the image layer's stream.

There is no magic marker at this level. An earlier version of this layer wrote a `b"INF2005"` marker into the medium while the image layer wrote none; the marker now lives in the shared payload envelope (`app/crypto/envelope.py`, magic `INF2005E`), so both media get the same "is there a payload here?" signal and the stego layer stays free of any knowledge of what the bytes mean.

Bits are written most-significant-bit first into the chosen number of lowest-order bits of consecutive scalar samples, in interleaved channel order, never wrapping. There is no realignment after the 32-bit header, so at depths that do not divide 32 the first payload bit sits partway through a sample. Depths 3, 5, 6 and 7 exercise that case.

## Start location

This layer takes a caller-supplied integer index and holds no key material. Deriving an index from a secret is a cryptographic operation and lives in `app/crypto/start_location.py`; the `passcode` parameter this layer once accepted was removed for that reason.

## What else each row checks

- **Max sample change against the bound.** Replacing the low *n* bits can move a sample by at most `2**n - 1`. A larger observed change would mean more was written than the depth accounts for.
- **Bits above the depth unchanged.** Asserted separately by `TestCoverPreservation`, over generated covers rather than one fixed file.
- **The cover file untouched on disk.** The layer refuses to write over its own input and writes atomically.

## What this does not establish

A successful round trip says nothing about authenticity. These bytes are opaque and unauthenticated at this layer: a wrong depth or start location can decode a plausible length and return wrong bytes with no error at all. The envelope magic and the signature above this layer are what establish that a payload is real. See `docs/limitations.md` §2.
